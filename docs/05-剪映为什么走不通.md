# 剪映为什么走不通

起点问题："剪映 codex 能操作、claudecode 不行，这是什么能力？" 一路查到底的结论。

## 一、所谓"codex 操作剪映"是什么能力

不是模型盯着屏幕点鼠标，绝大多数是**代码驱动**：
1. 直接生成剪映草稿文件（pyJianYingDraft 这类库，写草稿 JSON，剪映打开继续编辑）
2. 剪映 MCP server（把上面包成 MCP 工具，自然语言指挥）
3. 真 GUI 自动化（uiautomation 点窗口，很脆，只在 Windows + 剪映6 及以下）

本质是 **agentic coding**（工具调用 + 多步规划），不是 codex 独有黑科技。Claude Code 一样能接 MCP、跑 Python。

## 二、致命障碍：剪映 6.0+ 加密草稿

用户机器是剪映 **10.3.0**（VideoFusion-macOS.app），草稿目录 `~/Movies/JianyingPro/User Data/Projects/com.lveditor.draft`。

新版草稿格式是"多时间线"结构：
```
草稿/Timelines/project.json          (明文, 多时间线索引)
草稿/Timelines/<UUID>/draft_info.json (核心时间线数据, 加密!)
草稿/Timelines/<UUID>/attachment_*.json (明文辅助配置)
```

实测 `draft_info.json`（330KB）：
- 开头 `EGD4yTth0ADtB7xM6gSjbBaiy8FopIl1AAH58K9EFC3j/34B...`，末尾有 `==`
- base64 解码后 247KB 是高熵随机字节（前16字节 `1060f8c9...`，不是 gzip 的 `1f8b`、不是 JSON 的 `7b`）
- 结论：**base64(对称加密(JSON))**，真加密，不是可逆编码。tracks/segments/keyframes 全在这里面

## 三、全网现状（搜过最权威的）

- **pyJianYingDraft**（最主流剪映草稿库）白纸黑字：草稿/模板功能只支持剪映 **5.9 及以下**，6+ 加密是公开承认的 "unsolved challenge"，作者征集解密贡献
- **看雪逆向论坛**（国内最专业逆向社区）求助帖结论：没破解，没公开算法/密钥/解密代码。只有零碎 workaround（Windows 发布时 C 盘临时落明文 / 服务端 `draft_encryption_config` 开关），都不适用 Mac
- 加密是字节跳动主动设的防线，密钥在 app 二进制里

## 四、亲手验证（用 cliclick + accessibility 操作剪映）

发现剪映**首页**暴露 accessibility（能拿元素精确坐标），但**编辑器核心控件不暴露**（时间线/工具栏是自绘 canvas，只左侧素材树暴露）。

用 pyJianYingDraft 0.2.6 生成了一个旧格式草稿放进草稿目录，cliclick 双击打开 → 剪映直接弹 **"无法打开草稿"**（黄色警告框）。铁证：旧格式在 10.3.0 打不开。

## 五、为什么不破解加密

1. **合规**：绕过商业软件加密保护属反规避（DRM），违反剪映用户协议，多数地区涉嫌违法
2. **维护噩梦**：就算逆向出密钥，剪映每次更新可能换密钥/算法，得重新逆向。这也是为什么连专业社区都没维护出稳定方案

## 六、结论与出路

"用代码直接控制剪映 10.3.0 草稿"——物理上被加密堵死，不是能力不够。

出路是**绕开剪映**：
- 出片质量+效率 → Remotion 全代码管线（本工作台走的路，反而做出剪映难做的 WebGL 水波 + 真实数据 K 线）
- 要剪映特有特效 → 降级装剪映 ≤5.9（pyJianYingDraft 可用），或在剪映里手动剪、我截图当导演给参数
- 会员功能（花字/TTS/无水印）只能在剪映 GUI 里用，代码路进不去——为"让 AI 接管剪映"充会员没用
