# 经验总结

## 1. 结论

- **这类知识类竖屏视频可以 100% 用代码生成，不需要实拍 B-roll，也不需要图片/视频生成模型。** 原参考视频的中间画面是和内容无关的实拍素材（交易桌、看盘人群、背影）。改成"说到什么画什么"的数据动画、拟人角色和实景插画后，画面信息量比原片高。
- **"Claude 做视频"的本质是写代码出片。** Claude 不直接生成视频像素，而是写 HTML/CSS/JS 动画，再用无头 Chrome 逐帧截图，用 ffmpeg 编码。Remotion、HyperFrames、Claude Design Animations、Hypit 底层都是这一套。
- **最关键的设计：用配音驱动一切时间。** 逐句合成配音时量出每句的起止，字幕、口型、镜头、音效都挂在这张句级时间轴上。改文案后重跑，所有时机自动重排，不写死任何秒数。
- **选型：**

| 工具 | 定位 | 本次用法 | 结论 |
|---|---|---|---|
| **Remotion**（React） | 你的仓库已在用 | 最终生产版：`FupanStory` 合成里每帧 seek 一条 GSAP 时间线 | **日常生产用它**，和现有 NVDA / 寒武纪段落同一套命令 |
| **HyperFrames**（HeyGen 开源，HTML + GSAP） | 给 AI agent 用的 HTML 出片框架，自带 lint、check、快照 | v1～v3 的原型迭代 | 迭代快（lint/check/snapshot 很好用）；最终合并进 Remotion，避免两套技术栈 |
| **Hypit**（词级语义锚点，编译到 HyperFrames） | "事件绑在词上"、改文案/换配音自动重排、批量变体 | 前 25 秒试验 | **接入、不替代**。真人口播（时间事先不知道）价值最大 |
| Claude Design Animations | claude.ai 里的动画画布 | 借鉴了它"按词同步"的思路 | 适合单条手工打磨，不适合批量管线 |

## 2. 架构（生产版）

```
script.json（唯一需要改的文件：每句的角色 / 字幕 / 关键词 / 发音修正）
   │ make_vo.py（edge-tts 或 Kokoro，逐句合成 → 去首尾静音 → 按停顿拼接）
   ▼
vo.wav + timing.json（每句 start/end、每个场景 start/end）
   │ build.mjs + chars.mjs（场景 DOM、原创人物 SVG、作用域 CSS、GSAP 编排；事件时刻 = 句起止 / 句内按字插值）
   ▼
generated/{markup,styles,timeline}.ts ── FupanStory.tsx（Remotion：注入 DOM，每帧 tl.seek(frame/fps)，按 data-start/duration 控制可见窗口）
   │ subset.py（思源黑体按实际用字做子集，3 个字重各约 110KB）
   │ mix.py（配乐和弦随剧情变化 / 人声出现时音乐自动压低 / 高潮前抽空蓄力 / 卡点音效）→ loudnorm -15 LUFS
   ▼
npx remotion render … FupanStory → 1080×1920、30fps、56s
```

## 3. 实测数据

| 项目 | 数值 |
|---|---|
| 原参考视频 | 48.5s，720×1280，约 30 句字幕，5～6 段实拍 B-roll 套固定卡片模板 |
| v1 | 48.2s，文案与原片相同；Kokoro 配音速度 1.42 时约 6 字/秒，接近原片语速 |
| v2 / v3 | 56.4s（多了开头悬念句和结尾评论引导）；43 句、10 个场景 |
| Kokoro 默认语速 | 约 4.4 字/秒，偏慢；speed 设 1.38～1.42 才接近短视频语速 |
| HyperFrames 渲染 | 48s 用 4 分 20 秒；56s 用 5 分 30 秒（截图模式、软件 GPU） |
| Remotion 渲染 | 56s、并发 2、PNG 中间帧：约 17 分钟；成片 CRF 18 共 15MB |
| Hypit 渲染 | 25s（750 帧）、workers 2：全流程 4 分 16 秒，其中渲染帧约 2 分 20 秒 |
| 压缩发平台 | CRF 21 + maxrate 2.8M：56s 约 11MB，肉眼无差（平台会再压一次） |
| 响度 | 统一到 -15 LUFS / TP -1.5 |
| Hypit 对齐偏差 | 43 句窗口与配音起止最大差 0.033s（1 帧，帧量化造成） |
| 改文案重排 | 改 3 句 → 0 次手调时间；"三小时"锚点 0.467→0.900s，"今天的钱"锚点 18.2→19.63s，后续场景顺延最多 1.44s |

## 4. 抓人的设计手法（v2/v3 加的）

1. **第 0 帧就是封面**：大字"复盘 3 小时 / 第二天还是不知道买什么" + 困惑的小于。不用淡入，平台首帧可以直接当封面。
2. **3 秒钩子**："问题可能出在，你一开始就看错了东西" + 红章砸下。
3. **逐字点亮字幕**：念到哪个字就点亮哪个字，关键词变成金色并弹一下；说话人头像带口型（嘴巴开合按念这句话的时长驱动）。
4. **原创角色**：小于（年轻、眼镜、蓝卫衣）、阿本（灰鬓角、胡茬、衬衫）、5 个散户（帽子/波波头/光头眼镜/侧分/丸子头），由 `chars.mjs` 通用生成器按参数组合。
5. **实景**：深夜书房（时钟从 15:00 转到 23:47，再到次日 09:30；月落日出；台灯熄灭）、茶室（城市傍晚窗景、电视 K 线、茶杯冒热气）。
6. **拟人化概念**：散户先欢呼，"集体低开"时一个个惊恐、冒汗、下沉；"资金接力"是三个小人传一根 ¥ 接力棒。
7. **镜头**：每个场景都缓慢推镜（scale 1→1.045）；关键词上猛推一下（1.05～1.08）；"赚钱效应"出现时加闪光。
8. **声音**：失败段落和弦转小调；人声出来时音乐自动压低；高潮前 1.6 秒抽空音乐，riser 蓄力后重音落下；配有打字、钟表、硬币、盖章、灯泡等音效。
9. **结尾互动**：A/B/C/D 四选一 + 评论框打字"我先看 B" + 点关注（点击波纹）。选项式问题比"评论区聊聊"更容易让人留言。
10. **合规**：A 股红涨绿跌；图表标"示意数据"；底部写"交易认知分享·不构成投资建议"；只讲方法论，不荐股。

## 5. 踩坑清单（症状 → 原因 → 修法）

| # | 症状 | 原因 | 修法 |
|---|---|---|---|
| 1 | 字幕塌成一竖条，图表整体变暗 | 逐字 span 的类名 `.ch` 与图表面板 `.ch` 冲突 | 改名 `.cc`。新加类名前先 grep 一遍 |
| 2 | 场景切换时两个场景的内容叠在一起 | 出场动画延伸到下一场景 0.3s 内，与入场动画重叠 | 出场在 `end-0.28` 开始、`end-0.02` 结束，入场从 `start` 开始，窗口重叠只保留 0.08s |
| 3 | 模式卡片底部说明被裁掉 | 舞台高度不够 | 舞台从 860 加高到 960，卡片 SVG 高度调整 |
| 4 | 涨幅榜滚动时文字透过表头 | 表头背景是半透明的 | 表头改成不透明背景 |
| 5 | "小于这才发现"那一句约 1.4 秒画面全空 | 第一张卡片挂在第 2 句才出现 | 改为场景开始后 0.15s 就入场 |
| 6 | 改文案后字幕变了，对话气泡还是旧的 | 气泡文字写死在 build.mjs 里 | 从 script.json 读取（这是 Hypit 试验暴露出来的） |
| 7 | "哪只会涨"读成 zhǐ | misaki 的 G2P 多音字判断错误 | script.json 加 `tts` 字段：字幕显示"只"、读"支" |
| 8 | Kokoro 输出只有 0.6 秒 | v1.1 的注音格式喂给了 v1.0 模型 | 用 `kokoro-v1.1-zh.onnx` + `voices-v1.1-zh.bin` + `ZHG2P(version="1.1")` |
| 9 | `pip install jieba` 报 `install_layout` | Debian 系统 setuptools 的问题 | 用 venv 安装 |
| 10 | edge-tts / HF / HeyGen 连不上（403 / DNS） | 云端沙箱和你 Mac 的 Linux 工作区都走域名白名单 | 云端用 Kokoro 离线配音；edge-tts 在你 Mac 本机跑（7897 代理） |
| 11 | `npm ci` 卡 10 分钟后失败 | lock 文件里的地址都是 npmmirror，沙箱连不上 | 临时把 lock 里的域名换成 registry.npmjs.org 再安装，提交前换回去 |
| 12 | Remotion Studio 界面被样式污染 | 生成的 CSS 里有 `* {}`、`body {}` 这类全局规则 | build.mjs 给所有选择器加 `.fp-scope` 前缀，`#root` 改名 `#fp-root` |
| 13 | lint 报 `content_overlap` / `text_occluded` | 气泡盖住列表、表头盖住滚动行（都是故意的） | 元素加 `data-layout-allow-overlap` / `data-layout-allow-occlusion` |
| 14 | check 报对比度 1.9:1 | 弹入动画中途的半透明帧 | 瞬态帧，可以忽略；静态的免责小字调亮到 #8f9dbd |
| 15 | Hypit 构建被 SIGKILL | 多次构建残留的后台 worker 占内存，8GB 环境 OOM | 构建前清理旧 worker（`hypit runtime down`） |
| 16 | Hypit 程序内元素被宿主接管可见性 | `data-start`/`data-duration`/`data-composition-id` 这几个属性归 HyperFrames 宿主管 | 打包时改名为 `data-fs`/`data-fd` 并删掉 `data-composition-id` |
| 17 | Hypit 报 `DUPLICATE_EXPORT @hypit/temporal@1` | manifest 的依赖列表里 instant 和 window 属于同一个模块 | 依赖按模块去重 |
| 18 | `pkill -f xxx` 把自己的 shell 杀掉（exit 144） | 匹配到了当前命令行本身 | 用 pidfile 按 PID 杀进程 |
| 19 | 传文件到 Mac 失败 | 单个文件超过 20MB 上限 | 成片用 CRF 21 压到约 11MB；bundle 只打未推送的提交 |
| 20 | 重新生成把行尾空格带回来 | 模板里有一行只有缩进的空行 | build.mjs 输出时统一 `replace(/[ \t]+$/gm, "")` |
| 21 | 云端会话推不了 GitHub（403） | 仓库不在会话的授权仓库里；授权只在创建会话时生效 | 用 git bundle 交付，或新开一个选中该仓库的会话 |

## 6. Hypit 试验要点

- 接法：
  - `script.json` → Hypit Script：每句 = Selection + 字幕 Cue；7 个按词触发的事件 = Moment；发音修正 = Dual Text。
  - 已验收的 DOM/CSS/GSAP 原样打包成一个 browser program 组件，事件时刻全部取自对齐后的 Selection 和 Moment。
- **WhisperX 替身**：Hypit 自己不做对齐，词级时间只能来自 WhisperX 能力（本地需要 Hugging Face 模型，或者走付费托管的 HypiHub）。替身把 TTS 已知的逐字时间按 WhisperX 协议交给 Hypit。所以这次**测的是"Script→证据"的映射精度，不是声学对齐精度**。
- 限制：
  - Caption Fine 是统一样式的字幕，做不了关键词金色和说话人头像，要做得写项目自己的字幕组件。
  - 音效目前仍按我们自己的时间轴烘焙成一条轨，没有绑到 Moment 上。
- 许可证：Apache 2.0 附加条件。给自己、公司、客户做视频可以；做成多租户 SaaS 或出售衍生软件需要商业授权。

## 7. 下一步（按收益排序）

1. **换配音**：Kokoro 是最弱的一环。在你 Mac 上 `run.sh` 默认走 edge-tts（云扬/云健/云希）；再往上可以接火山/豆包 TTS，或者克隆纪总本人的声音。
2. **接真实数据**：把量化系统算出的昨日涨停今日溢价、连板高度、炸板率喂进"验证一/验证二"的图表，每天自动出"今日赚钱效应"，替换掉现在的示意数据。
3. **开头 A/B 测试**：同一期出 3 个开头，看 3 秒留存和完播率。
4. **真人口播接 Hypit**：纪总出镜录音 → 真 WhisperX 对齐 → "放量/缩量/突破"设成 Moment，K 线图卡按词出现。
5. **音效也绑到词上**：Hypit 里用 `audio:Item at={copy.story.moment.xxx}`，改文案时音效跟着词走。
